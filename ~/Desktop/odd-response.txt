3. CAMERA IMAGE CAPTURE ERRORS ANALYSIS

=== 3 SURFACES ANALYSIS ===

1. EvidenceCaptureModal.vue - Receipt evidence photos
2. ScanPanel.vue - ULD code scanner (BarcodeDetector + ZBar WASM fallback)
3. BarcodeCameraModal.vue - Reusable camera modal (ZBar WASM + native BarcodeDetector)

=== ROOT CAUSES IDENTIFIED ===

| Error Type | Cause | Affected Component(s) | Fix |
|------------|-------|----------------------|-----|
| Blank canvas / 0×0 image | Capture before video.readyState >= 2 + real videoWidth/videoHeight | EvidenceCaptureModal.vue, CameraCapture.vue | ✅ Added readiness check |
| Camera stuck / light on without UI | getUserMedia resolves → stream.getTracks().stop() not called when modal closes | All camera components | ✅ Added stream cleanup |
| iOS camera disabled | No muted attribute on <video> → iOS blocks autoplay without mute | BarcodeCameraModal.vue | ✅ Added muted attribute |
| No frame ready → detector GPS | Detectors fire before any frame decoded → infinite scan loops | ScanPanel.vue, BarcodeCameraModal.vue | ✅ Added waitForFrame(video, 5s) |
| ZBar WASM init failure | Rollup module bundling breaks ZBar inlined import | BarcodeCameraModal.vue | ✅ Served from /public/zbar-inlined/ |
| getUserMedia only in secure contexts | HTTPS or localhost required → fails on HTTP tablets | All camera components | ✅ Fallback to input[type="file"] with capture="environment" |
| NotAllowedError / SecurityError | User denied camera permission → no feedback, user stuck | All camera components | ✅ Map to concrete messages + "Retry" button |
| Device not found | No camera hardware → graceful error + retry | All camera components | ✅ Specific error messages per error name |

=== FIX PATTERNS APPLIED ===

1. Readiness check: video.readyState >= 2 && video.videoWidth > 0 && video.videoHeight > 0 before any canvas operations
2. Stream cleanup: releaseAllStreams() called before new getUserMedia, in watch(show), on beforeUnmount
3. Error mapping: Specific messages per NamePattern (NotAllowedError, NotFoundError, NotReadableError)
4. Fallback chain: getUserMedia → device enumeration → video: true basic → file input with capture="environment"
5. 3-second de-dupe: shouldScan(code) with lastDetectedCode + Date.now() window
6. iOS support: muted attribute + environment facing mode fallback

Tablet Issues:

=== 4.6 WAREHOUSE RECEIPTSView.vue ===

Tablet Issues:
- ❌ Filtro EN_PROCESO → rama especial comparaba !isReceiptComplete(m) equivalía a PENDIENTE
- ❌ Pipeline segmentado → ancho visualizaba volumen pero filas no se colapsaban
- ❌ Botón emit desaparecía en renderMawbs/useLiveRefresh

Fixes Applied:
- filteredMawbs filtra TODOS los estados uniformemente mawbOperationalStatusMap[m.id] === statusFilter
- Pipeline segmentado con 6 segmentos proporcionales al conteo (seg.width = count/total %)
- setStatusFilter(key) - click en segmento = filtro; re-click = limpiar
- receiptTotals/receiptById excluyen DRAFT (isDraftReceipt(r))
- executeEmit() usa updateEmit (PUT /{id}/emit) en lugar de createCorrection
